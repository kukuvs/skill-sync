## Техническое задание (ТЗ)

**Название:** `skill-sync` — CLI для синхронизации скилов AI-агентов из Bitbucket

**Цель:** Обеспечить совместное использование скилов между разработчиками через централизованное хранилище в Bitbucket. Библиотека загружает скилы в локальный проект, отслеживая зависимости через файл `skill-lock.json`.

---

### Функциональные требования

1. **Загрузка скила по имени**  
   Команда проверяет наличие `skill-lock.json`:
   - Если файл отсутствует — создаёт новый с указанным скилом.
   - Если файл существует — добавляет скил в список (без дубликатов).  
   Затем скачивает содержимое скила из Bitbucket в папку проекта `.skill/<имя-скила>`.

2. **Загрузка всех скилов по lock-файлу**  
   Читает `skill-lock.json` и последовательно скачивает каждый перечисленный скил в `.skill/`. Если какой-то скил уже существует — перезаписывает (или пропускает — на усмотрение реализации, но с уведомлением).

3. **Поиск и интерактивный выбор скилов (опционально, «со звёздочкой»)**  
   Позволяет через CLI-интерфейс:
   - вывести список доступных групп и скилов из Bitbucket (с учётом вложенности);
   - выбрать нужные скилы с помощью стрелок/пробела;
   - автоматически добавить выбранное в `skill-lock.json` и загрузить.

---

### Формат skill-lock.json

Хранится в корне проекта. Пример:

```json
{
  "skills": [
    "разработка/x-uikit",
    "разработка/x-uikit/button",
    "тестирование/jest-config"
  ]
}
```

---

### Структура репозитория Bitbucket (источник)

```
<базовый-URL-репозитория>/
  группы/ (например, "разработка", "тестирование", "анализ")
    <скил-имя>/
      ... (любые файлы скила)
    <скил-имя>/<подскил>/    (поддержка вложенности, см. пример x-uikit/button)
      ...
```

- На верхнем уровне — папки-группы.
- Внутри — папки скилов.
- Возможна произвольная глубина вложенности (на практике 2–3 уровня).
- Скил идентифицируется путём относительно корня репозитория, например: `разработка/x-uikit/button`.

---

### Команды CLI (запуск через `npx`)

| Команда | Аргументы | Действие |
|---------|-----------|----------|
| `skill-sync add <skill-path>` | `skill-path` — путь в репозитории, например `разработка/x-uikit` | Добавляет скил в lock-файл и загружает |
| `skill-sync sync` | нет | Загружает все скилы из `skill-lock.json` |
| `skill-sync search` | нет (опционально фильтр) | Интерактивный поиск/выбор скилов из Bitbucket |

- Все команды должны быть доступны через `npx skill-sync <command>`.
- При первом запуске запрашивать (или читать из переменных окружения) `BITBUCKET_TOKEN` и `BITBUCKET_REPO_URL`.

---

### Технические ограничения

- **Язык:** JavaScript или TypeScript (сборка в JS для публикации в npm).
- **Сторонние библиотеки:** минимум. Разрешены: `node-fetch` (или встроенный `fetch` в Node 18+), `commander` (разбор команд), `inquirer`/`prompts` (для интерактива — опционально). Всё остальное — нативные модули Node.js (`fs`, `path`, `child_process` при необходимости, `readline`).
- **Транспорт:** только HTTP(S) к Bitbucket REST API (например, получение содержимого директории и файлов через API с токеном). Поддержать рекурсивную выкачку папок.
- **Авторизация:** HTTP Access Token (передаётся в заголовке `Authorization: Bearer <token>`).
- **Папка назначения:** `.skill/` в корне проекта, где выполняется команда.
- **Обработка ошибок:** понятные сообщения в консоли (невалидный токен, отсутствие скила в репозитории, проблемы с сетью).

---

### Пример использования

```bash
# Установка глобально (или через npx)
npm install -g skill-sync

# Экспорт переменных (или .env файл)
export BITBUCKET_TOKEN=xxx
export BITBUCKET_REPO_URL=https://bitbucket.org/team/skills-repo

# Добавить скил разработки
npx skill-sync add разработка/x-uikit

# Добавить вложенный скил (он автоматически появится в lock-файле)
npx skill-sync add разработка/x-uikit/button

# Загрузить всё, что указано в lock-файле
npx skill-sync sync

# (со звёздочкой) Найти и выбрать скилы
npx skill-sync search
```

Результат: в проекте появляется папка `.skill/разработка/x-uikit/` и `.skill/разработка/x-uikit/button/` с файлами из репозитория.

---

### Критерии приёмки

- Запуск через `npx` работает без глобальной установки.
- Скилы корректно скачиваются с учётом вложенности (создаются все промежуточные папки).
- `skill-lock.json` правильно обновляется при `add` (не дублирует, сохраняет порядок).
- `sync` не выдаёт ошибку, если lock-файла нет (выводит предупреждение).
- Интерактивный поиск показывает древовидную структуру групп/скилов с возможностью выбора нескольких.
